# Especificación Técnica - AGT-0001

## 1. Visión General y Propósito
El objetivo de AGT-0001 es dotar al proyecto `agente_dev` de una interfaz de línea de comandos (CLI) instalable (`agt` / `agente-dev`) que automatice la gestión de tareas del workflow, garantice la creación de ramas de Git estandarizadas para cada tarea y verifique los Quality Gates de forma programática.

## 2. Requerimientos Funcionales
1. **Comando `task:new <ID>`**:
   - Parámetros: `<ID>` (ej. `AGT-0002`), `--title <string>`, `--type <feat|fix|refactor|docs|test|chore>`, `--owner <string>`, `--base <string>`.
   - Genera:
     - `docs/workflow/tasks/<ID>.yml` (a partir de `templates/task-manifest.yml`).
     - `docs/workflow/specs/<ID>.md` (a partir de `templates/specification.md`).
     - `docs/workflow/plans/<ID>.md` (a partir de `templates/implementation-plan.md`).
     - `docs/workflow/tests/<ID>.md` (a partir de `templates/test-plan.md`).
   - Automatización Git:
     - Calcula el nombre de la rama: `<tipo>/<ID>-<slug>` (ej. `feat/AGT-0002-mi-nueva-feature`).
     - Conmuta a la rama (`git checkout -b ...`). Si la rama ya existe, hace checkout.

2. **Comando `task:branch <ID>`**:
   - Lee el manifiesto `docs/workflow/tasks/<ID>.yml` y cambia o crea la rama correspondiente.

3. **Comando `task:verify <ID>`**:
   - Lee los `quality_gates` y `commands` del manifiesto y los ejecuta secuencialmente.

4. **Comando `task:list`**:
   - Lista todas las tareas en `docs/workflow/tasks/` y su estado (`PLANNED`, `IN_PROGRESS`, `DONE`, etc.).

## 3. Criterios de Aceptación
- La herramienta se puede instalar globalmente con `npm link` o `npm install -g .` y responder al comando `agt --help`.
- Toda nueva tarea creada genera los 4 archivos estructurados en `docs/workflow/` y conmuta a la rama de Git correspondiente.
- Validación de que el repositorio no esté en un estado de conflicto antes de crear ramas.
- Cobertura de pruebas unitarias sobre los módulos de Git, TaskManager y CLI.
