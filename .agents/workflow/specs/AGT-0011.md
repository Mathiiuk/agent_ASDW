# Specification — AGT-0011

## 1. Objetivo
Permitir activar un **modo de desarrollo por fases** donde cada feature se valida con un check antes de avanzar, los bugs generan fixes/hotfixes trazables y todo queda documentado en una bitácora en `docs/`.

## 2. Problema actual
El flujo solo gestiona tareas aisladas (`task:new` / `task:loop`). No hay forma de encadenar varias features, garantizar que no se avance con bugs abiertos, ni dejar un registro consolidado del desarrollo.

## 3. Resultado esperado
Flujo `feat → check → siguiente feat`; bug en check → `fix`; healthcheck final; bug en healthcheck → `hotfix`; bitácora `docs/bitacora/<PLAN-ID>.md` actualizada en cada paso.

## 4. Alcance

### Incluido
- Módulo `src/phase-runner.js` (estado en `.agents/workflow/phases/`, puntero `ACTIVE`).
- Comandos `agt phase:start | phase:check | phase:health | phase:status`.
- Tareas de corrección `<TASK-ID>-FIX-<n>` y `<PLAN-ID>-HOTFIX-<n>` heredando gates.
- Documentación en regla maestra y README.

### No incluido
- Herramientas MCP para el modo por fases.
- Ramas Git por fase (todo el plan vive en la rama activa).

## 5. Criterios de aceptación

- [x] AC-01: Un check en verde marca la feat `READY_FOR_PR` e inicia la siguiente.
- [x] AC-02: Un check fallido crea un único fix abierto por fase y bloquea el avance hasta volver a verde.
- [x] AC-03: El healthcheck solo corre con todas las fases en verde; si falla crea un hotfix, si pasa completa el plan y desactiva el modo.
- [x] AC-04: La bitácora en `docs/bitacora/` registra fases, fixes/hotfixes, healthcheck y eventos cronológicos.
